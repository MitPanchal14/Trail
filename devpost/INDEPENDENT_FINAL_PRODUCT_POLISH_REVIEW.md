## Source and scope assessment

`append-action` is a stopped-session append-only command; existing general-editor ordering restrictions remain. Pause uses the existing trusted interval path and commit before showing capture. Save/Cancel never Resume or end the current block. Pending operations remain owned by the existing write/LocalStore Retry pathway.

Queued goals are canonical schema1 goal/action records with validated `queued` status and maximum10. Old schema1 fixtures without queued records still validate. Queued records cannot contain completed/recorded work, contexts, sessions or goal events; editing only targets queued records. Optional fields and new targets receive validation before receipt replay. Activation requires no open goal/session and retains original IDs; one-open-goal and session-next-action invariants remain. Existing revision rules invalidate unrelated Undo. This establishes old-record compatibility with the current build, not downgrade compatibility with pre-queue application code.

Shared blue/indigo/violet archive/Focus changes and pending-only mountain-path indicator match the agreed direction. Planner markup now renders actions directly instead of replacing strings. Server/model/config are unchanged. The new fictional capture scenario is explicitly a read-only in-memory illustration, not a functional simulated queue; this was permitted by the prompt and is labelled accurately. Its exploration/reset preserves real records.

Intentional scope limits: Later capture is manual; Gemini planning remains the reviewed new-active-goal flow. Queued goals wait until active work is finished; arbitrary switching between unfinished goals and simultaneous timers were not requested in this bounded implementation. No deletion/reordering of queued goals or new AI behaviour was added. The optional delayed waiting sentence was omitted, avoiding a new timer lifecycle; factual pending status and cancellation remain.
