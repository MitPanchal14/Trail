## Intended result

One connected, crafted experience: first-visit landing → Start working → saved next action → atmospheric focus → immediate Pause/save → Resume → small completion → selectable goal journey → final review → explicit major reward → finished collection. A returning user reaches saved work directly. In this proof, make first visit and returning scenarios explicit and fictional; no real storage/auth. Initial preview may show landing, while the Returning Today shortcut remains available.

### Composition and interaction

1. **Landing:** beautiful compact hero, expressive “Nail the Trail” headline if it fits, plain explanation of focus/save/return, one dominant “Start working” action. The action enters the actual working proof; it does not start the clock or complete anything. Quiet brand/Home route returns to landing. Use an original live version of the journey art, no unrelated stock 3D hero, fake statistics/testimonials, pricing wall or long text tour.
2. **Today:** strongest visual emphasis on exact saved next instruction and Resume. Create a deliberate work stage using spacing, type, grouping and selective colour; avoid making every paragraph a card. Optional context stays available. Make completed-step acknowledgement feel earned: restrained finite gradient/check treatment then a clear next action. Preserve exact saved instruction on Focus and Undo. Keep daily journey supportive.
3. **Journey graphic:** improve the main metaphor beyond the stacked contour relief. Use the latest brief’s luminous route with deliberate milestone surfaces, saved marker and restrained depth as the single design hypothesis. It must read as accumulated work. Keep daily versus whole-goal scale and all factual information accessible. Current/completed/planned/unfinished are distinguishable without colour alone. Added fifth step has coherent counts/identity; minute totals/geometry remain labelled illustrative.
4. **Subtask interaction:** hover gives a coordinated gradient highlight without moving content; keyboard focus and tap/selection give equivalent feedback. Highlight associated route segment/marker and show the selected record’s own context in a stable detail surface. No hover-only facts or generic neon outlines on all elements.
5. **Focus:** centered stable work window over slowly moving soft gradient fields/shapes; task, timer and Pause/Complete clearly grouped. On narrow screens keep essential controls accessible before decorative material. Use a restrained roughly 24–36s low-amplitude ambient cycle as a starting point, with a visible still/ambience control and static reduced-motion rendering from first paint. No particles, constant timer pulses, audio or claimed attention benefits. Text contrast must not depend on animation frame. Keep long saved instruction/context readable; Pause must remain readily reachable.
6. **Final review and achievement:** visually compose a small completion summary and goal token rather than just stacking equal buttons. One clear confirmation; add-step/keep-open secondary but easy to find. Major reward only on explicit confirmation; more of the coordinated screen-wide colour transition should be visible than in the current opaque-card-heavy overlay. Preserve finite animation, immediate exit, static reduced-motion equivalent and consistent finished history; no repeated reward from navigation. Neutral surrounding page with colourful finished record.
7. **Dark theme proof:** semantic tokens and an accessible Light/Dark control. Inspect landing, Today, journey, focus, review, reward and finished states in both. Deep neutral surfaces, clear typography and composed gradients; no blind inversion or old dark-glass/pixel styling. In-memory theme is sufficient here. Do not add production theme persistence or an OS-default policy without a later contract.

The hierarchy is a design hypothesis, not measured audience eye tracking. No new APIs or external media needed. Prioritise composed clarity over adding more effects. Make decorative SVGs noninteractive and keep route labels/details usable.
