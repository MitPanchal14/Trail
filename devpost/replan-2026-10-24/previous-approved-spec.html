Canonical technical spec · Product behavior · Visual reference

Where things live

No account or cross-device sync. Clearing site data removes records unless backed up. Only submitted planning text/context goes to Gemini; ordinary sessions stay local. Production AI stays disabled until real abuse protection is verified.

Explore the core journey

TaskCreation retains typed text or a corrected voice transcript. Unsupported voice keeps typing usable. Nothing is accepted yet.

Timer and recovery

FocusView and lib/timer.ts persist heartbeat snapshots. Open background tabs continue timing. Startup restores the last durable remaining time, marks unfinished work interrupted and asks for Resume. Closed absence receives no time credit. Recovery can be older than one second if the browser throttles saving.

Stable trail and corrections

Immutable subtask slots keep earned checkpoints in place after reordering. Colour derives from active completion records. Undo removes only mistaken credit. Reopen preserves a genuine summit; Correct mistaken goal completion revokes erroneous glow.

Calendar and truthful reports

Record event dates in a fixed first-use browser timezone. Counts use actual completion dates. Removed/deferred commitments remain in history. A nonempty committed set must be completed on its date for the all-done marker. No productivity-growth claims.

AI and manual fallback

app/api/plan/route.ts bounds inputs and validates outputs. GEMINI_API_KEY stays server-only. Missing keys, invalid responses or limits preserve the draft and offer manual editing. Verify provider model/quota during implementation.

Backup and errors

lib/storage.ts validates versioned snapshots. Blocked or corrupt storage displays a persistent warning and export path. Import validates data and asks before replacing existing records. Sample data is separate from personal history.

Build and verification

First review the visual Today slice. Then prove persistent save/resume, add reviewed planning, derive Mountains/Progress and deploy. Checklist tests cover timer recovery, idempotency, stable positions, calendar boundaries and the real browser journey.

How to run it once built

npm ci → npm run dev → localhost:3000. Planned checks: lint, typecheck, test, test:e2e and build. These scripts will be created in slice 1; no application test success is claimed here.

First deployment is part of the learning goal. Inspect the public app from a fresh browser, document actual limits and prepare source/video separately. This blueprint does not authorize submission.
